## How the leaderboard works

There is no per-user prediction-accuracy or calibration score. The leaderboard ranks users strictly by **Schmeckle balance** — `ORDER BY schmeckles DESC` (`features/users_repo.py`).

Balance moves only when a contract resolves:

- **Won contract** — the holder's Schmeckle balance increases by `max_payout`.
- **Expired contract** — no payout; balance is unaffected.

There is no separate "accuracy" or "calibration" metric anywhere in the schema or API. Buying a contract that resolves YES simply pays out; there is no bonus for having bought in at a worse implied probability.

## Leaderboard

The leaderboard is served from `GET /users/leaderboard` and rendered by the `LeaderboardTable` component. Each row shows Schmeckle balance, total contracts, open contracts, and won contracts (`LeaderboardUser` model).

Users with zero resolved contracts still appear on the leaderboard — ranking is purely by balance, so a new user (starting at 1000 Schmeckles) is ranked alongside everyone else.
