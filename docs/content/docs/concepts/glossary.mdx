---
title: "Glossary"
description: "Key terms used across Polydelve docs."
---

## Contract

A bet on a target package. A YES contract wins if a qualifying event happens before the deadline (a CVE meeting a CVSS threshold, an EPSS crossing, or a MAL advisory), and can win before expiry. A NO contract wins if no CVE meeting the CVSS threshold appears before the deadline. Statuses are `open`, `won`, `lost` (NO bet hit early), `expired` (YES bet reached its deadline), and `sold`. A win pays `max_payout` bits.

## NO bet

A contract with `direction='no'`: it bets that a package gets no new CVE at or above the CVSS threshold before expiry. CVSS-only, and only offered on packages with a CVE in the last 100 days.

## Basket

A slip with two or more packages and a `threshold_count`. It wins when that many members have hit their win conditions.

## CVE

Common Vulnerabilities and Exposures. A public identifier assigned to a disclosed software vulnerability (e.g. `CVE-2024-12345`). New CVEs at or above a CVSS threshold are the main contract signal on Polydelve.

## CVSS

Common Vulnerability Scoring System. A numeric severity score from 0 to 10 assigned to a CVE. Higher scores indicate greater severity. Contracts specify a minimum CVSS as part of their resolution criteria.

## EPSS

Exploit Prediction Scoring System. A daily probability score between 0 and 1, published by FIRST, expressing the likelihood that a CVE will be exploited in the wild within the next 30 days. Polydelve ingests FIRST's daily bulk CSV for both current scores and history, uses EPSS to price contracts, and treats an EPSS crossing as an independent YES win condition (see [Market Resolution](/docs/concepts/market-resolution)).

## EPSS History

A time-series of daily EPSS values for a given package or CVE. Polydelve stores this history to draw trend charts and to settle EPSS win conditions.

## Grade

A 0–10 danger score for a package, computed from CVE count, EPSS, max CVSS, and MAL status. Display only; it does not affect payout.

## Hazard (λ)

The daily rate at which new qualifying CVEs arrive for a package, estimated from the last 90 and 365 days of CVE history. It drives all pricing (see [Prediction Markets](/docs/concepts/prediction-markets)).

## MAL Advisory

A malicious package advisory sourced from OSV. Unlike CVEs, MAL advisories flag packages that are themselves intentionally harmful (e.g. typosquats, dependency confusion attacks). A MAL advisory published after purchase is a YES win condition.

## max_payout

The number of bits returned to a contract holder on a win. Equivalent to `max_payout = cost × multiplier`.

## Multiplier

The payout-to-cost ratio for a contract. A multiplier of 3 means a 10-bit purchase returns 30 bits on a win. Higher multipliers reflect lower implied probability of the event occurring.

## OSV

Open Source Vulnerabilities. A database aggregating vulnerability advisories across ecosystems. Polydelve uses OSV for CVE history and MAL advisories on npm and PyPI packages. Contracts can also resolve on an EPSS crossing, independent of OSV CVE data (see [Market Resolution](/docs/concepts/market-resolution)).

## relevancy_score

A numeric field on featured contracts, returned by `GET /featured-contracts`, used to rank them. Higher values indicate contracts Polydelve considers more timely or significant. The web app does not currently display it.

## Slip

The bet slip on the Predict page where you add packages, choose YES or NO, and set thresholds, duration, and stake before buying.

## Bit

Polydelve's in-app currency. New users start with 1000 bits; balance changes only from buying contracts and collecting payouts on wins. They have no real-world monetary value and exist solely for ranking and gameplay purposes.
